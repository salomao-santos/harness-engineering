# Project Structure Guide (`structure.md`)

## Purpose

`structure.md` tells AI tools where code lives, how files are named, and what can import what. When an AI creates a new component, hook, API route, or test, it uses this document to decide the path, filename, and import style — so generated code fits seamlessly into the existing codebase.

## Section Breakdown

### Directory Tree (required)

Annotate every non-obvious folder with a one-line purpose. Keep to 2–3 levels deep — deeper is rarely needed.

**Good:**
```
src/
├── features/           # Self-contained feature modules (auth, tasks, billing)
│   └── tasks/
│       ├── api/        # React Query hooks that call the tasks API
│       ├── components/ # Task-specific UI components
│       ├── hooks/      # Task-specific custom hooks
│       └── index.ts    # Public API for this feature — only export from here
├── shared/             # Cross-feature utilities, types, UI primitives
│   ├── components/     # Generic UI (Button, Modal, Input)
│   ├── hooks/          # Generic hooks (useDebounce, useMediaQuery)
│   └── utils/          # Pure functions (formatDate, slugify)
├── routes/             # React Router file-based routes (maps to URL structure)
├── server/             # Express app (only in monorepo — else separate package)
│   ├── routes/         # Route handlers organized by resource
│   ├── middleware/      # Express middleware (auth, validation, logging)
│   └── services/       # Business logic, called by route handlers
├── prisma/             # Prisma schema and migrations — do not edit migrations manually
├── docs/
│   └── rules/          # AI steering documents (product, tech, structure, patterns)
└── tests/              # Integration and E2E tests only — unit tests co-located
```

**Bad (no annotations):**
```
src/
├── components/
├── hooks/
├── utils/
├── pages/
└── api/
```

### Naming Conventions (required)

Use a table. Cover every artifact type used in the project.

| Artifact | Convention | Example |
|----------|-----------|---------|
| React components | PascalCase `.tsx` | `TaskCard.tsx` |
| Custom hooks | `use` prefix, camelCase | `useTaskList.ts` |
| Utility functions | camelCase `.ts` | `formatDueDate.ts` |
| Constants / enums | SCREAMING_SNAKE_CASE | `TASK_STATUS.ts` |
| Directories | kebab-case | `task-details/` |
| API route files | kebab-case | `task-comments.ts` |
| Test files | Same name + `.test.ts(x)` | `TaskCard.test.tsx` |
| Types / interfaces | PascalCase, no `I` prefix | `TaskPayload`, `UserSession` |
| Prisma models | PascalCase singular | `Task`, `User`, `Project` |
| Database tables | snake_case plural | `tasks`, `project_members` |
| Env variables | SCREAMING_SNAKE_CASE | `DATABASE_URL`, `JWT_SECRET` |

### Module Boundaries (required if layered architecture)

Define what can import what. Prevents circular dependencies and enforces layering.

**Arrow = allowed import direction.**

```
routes/ → services/ → repositories/ → prisma client
routes/ → middleware/
features/* → shared/*
features/A ↛ features/B   (features never import each other)
shared/ ↛ features/*       (shared never imports features)
```

Notation:
- `A → B` means A may import from B
- `A ↛ B` means A must never import from B

### Co-location Policy (required)

Describe where tests, styles, and type files live relative to source.

```markdown
- Unit tests: co-located next to source as `*.test.ts` / `*.test.tsx`
- Integration tests: `tests/integration/` — grouped by feature
- E2E tests: `tests/e2e/` — grouped by user flow
- Component styles: co-located as `*.module.css` (CSS Modules)
- Shared global styles: `src/styles/`
- Feature-level types: `types.ts` inside each feature folder
- Shared types: `src/shared/types/`
- Generated code: `src/generated/` — never edit manually
```

### Special Files (optional but useful)

Call out non-obvious files the AI should know about.

```markdown
- `src/routes/_layout.tsx` — root layout, wraps all pages with Providers
- `prisma/schema.prisma` — single source of truth for DB schema; run `pnpm db:generate` after edits
- `.env.example` — documents all required env vars; `.env` is gitignored
- `pnpm-lock.yaml` — do not edit manually; regenerated by `pnpm install`
```

## Common Anti-Patterns

| Anti-pattern | Problem | Fix |
|-------------|---------|-----|
| Tree with no annotations | AI can't infer purpose from name alone | Add one-line comment per folder |
| Mixing co-location and centralized tests | AI puts tests in wrong place | Pick one policy, document it |
| No module boundaries | AI creates cross-feature imports | Add explicit boundary rules |
| Listing every file | Noise, not signal | Top 2–3 levels only |
| Inconsistent naming table | AI picks arbitrarily | Complete the table for all artifact types |

## Length Target

- Tree: 20–40 lines with annotations
- Naming table: 8–15 rows
- Boundaries: 5–10 rules
- Total document: < 100 lines
